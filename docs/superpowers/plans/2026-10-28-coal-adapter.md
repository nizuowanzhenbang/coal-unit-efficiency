# PP-050 首个适配单元：带血缘的能效预览

按用户自主迭代授权直接执行；使用既有 FastAPI/Pydantic/能效算法，不引入服务。

## 设计与取舍

目标：显式绑定一个来源实例的煤批次、化验与一个本地机组、时间窗口，把收到基低位热值换算后实际送入既有 compute_record，返回能效预览和完整血缘。
选择无持久化预览而非自动回填生产快照：入厂化验不等于实际入炉测量，当前没有经过核对的批次消耗分配。结果明确为用户指定批次的情景估算；不会制造运行实测记录。旧无血缘缓存保持兼容，但新路径不读取它。
Ruling: 本单元仅实现每次请求的显式批次到机组关联，不建立永久映射或自动推送 — 现有代码缺乏入炉分配事实 — 代价是以后仍需实现持久映射与实际消耗验证，PP-050总体保持进行中。

契约 coal-quality-energy/v1：来源系统固定 coal-quality-monitor，实例、批次ID、化验ID必须非空；映射的实例/批次必须等于测量来源，目标按唯一机组code查找，不能按名或跨库id猜测。Qnet/ar，单位kcal/kg或kJ/kg，沿用4.1868。热值>0且<=10000 kcal/kg等价。显式时区必填，统一UTC返回；化验不能晚于工况，关联窗口左闭右开。返回原值/单位、换算因子、原时间及UTC时间、来源身份、机组关联、版本、测量年龄、估算结果。未知字段拒绝。

## 验收与审查重点

来源同ID不同实例不混用；显示名不参与关联；未知基准不得推断；时区跨日一致；极值不得产生NaN/Infinity或污染账本。数据库身份由目标code核对。真实化验导出传输、持久化映射、跨系统exactly-once及现场有效性不在本单元范围。
